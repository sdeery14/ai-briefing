# v0.3 reconciliation — independent review findings and their resolution

Maps every P0 and P1 finding in [`architecture-review-v0.2.md`](architecture-review-v0.2.md) to what [RFC v0.3](../rfc/AI-Briefing-RFC-v0.3.md) and the revised [ADRs](../adr/README.md) now say. P2 and P3 findings are summarised at the end.

Status values:

- **Resolved** — the documents now specify the fix.
- **Resolved, verification pending** — the design is fixed; a fact must still be checked on the host or in GitHub before the milestone named.
- **Resolved differently** — the owner chose a different remedy from the one the review proposed.

## P0 findings

| Finding | Resolution | Where | Status |
|---|---|---|---|
| **F-01** Value is validated last; no baseline | Walking skeleton: M1 produces a real briefing after its first six issues, then runs daily; M2 puts it in the morning email. A single-prompt baseline digest is built in M1 and kept as a permanent comparison arm, with blind preference recorded daily. The M1 exit report includes a recommendation to simplify if the baseline is preferred. | RFC §1.1, §12; milestones M1, M2; ADR-007 §4 | Resolved |
| **F-02** The seed benchmark cannot measure the ranking engine | The benchmark is a calibration aid and smoke test. Deterministic tests are the hard gates. Prospective evaluation with 15–20 minutes of owner time a week is the primary measure. Sample sizes, intervals and run-to-run variability are mandatory in reports. No accuracy thresholds until a baseline exists. Blind-holdout tooling is dropped. | ADR-007; RFC §10.2; milestones M4 | Resolved |

## P1 findings

| Finding | Resolution | Where | Status |
|---|---|---|---|
| **F-03** Story grouping has no mechanism; membership is not versioned | M1 groups by shared or linked canonical URL. M3 adds a lexical shortlist confirmed by a constrained model answer. Every membership change is an append-only event. Each assessment records the exact observations it saw. A grouping trial on M1 data confirms the M3 design before it is built. | ADR-003; ADR-002 §3–4; RFC §4 step 6, §5 | Resolved; mechanism to be confirmed by the M1 trial |
| **F-04** Evidence is not a record; citations cannot be verified | `EvidenceItem` records. The model cites only supplied IDs and never outputs URLs. Code checks that quotes occur in stored text. Integrity status and semantic support are separate fields, and the documents state that a verified quote does not prove the claim. Source roles and independent corroboration are defined. | ADR-004; RFC §4 steps 7–8, §5, §6 | Resolved |
| **F-05** The assessment mixes four decisions | Assessment (model), policy (code) and selection (code) are separate steps with separate records. `merge` and placement are removed from the assessment. `EditorialDecision` holds the policy outcome. | ADR-004; RFC §3.2, §6 | Resolved |
| **F-06** Volume and cost are unmodelled | A screening tier precedes assessment. A provisional $15 monthly budget is enforced before each call from recorded usage, with a shedding order and defined degraded behaviour. Prices are now verified against Anthropic's documentation; real volume is measured in M1 and reported at its exit. | RFC §7; ADR-009 (cost control); milestones 1.5, M1 exit report | Resolved; the budget figure is provisional until M1 measurements |
| **F-07** No feedback channel | An authenticated Home Assistant page reached from the email. `GET` changes nothing; feedback is recorded only on an authenticated `POST`. Home Assistant writes event files; AI Briefing validates and ingests them idempotently. | ADR-006; RFC §8.4; milestones M2 | Resolved; the Home System change is the owner's to build |
| **F-08** Content rights and retention unresolved | New ADR-010: metadata and permitted summaries kept; bodies private for up to 90 days where terms permit; permitted excerpts and hashes kept longer; per-source terms recorded before a source is enabled; no third-party text in the repository. Hacker News is the only community source; uncatalogued hosts are metadata-only. | ADR-010; ADR-003; RFC §11 | Resolved |
| **F-09** Judge plan exceeds the labelled data | **Resolved differently.** The review recommended no judges in V1. The owner permits experimental judges earlier, for diagnosis only. They never gate anything until agreement with owner labels is measured and the owner approves. | ADR-007 §6; RFC §10.2 | Resolved differently |
| **F-10** Observability over-scoped; MLflow risks | SQLite and structured logs are the record. `LLMCall` persists every model call. MLflow tracing is optional and limited to model calls, job roots and a few important operations, through a no-op-by-default protocol. Lightweight client, bounded flush, and a test with the server unreachable. Evaluation is independent Python. The store is treated as agent-readable. | ADR-009; RFC §10.1 | Resolved, verification pending: client compatibility with the running server (M0 item 0.12, gates M2) |
| **F-11** `/round` guardrails are instructions, not mechanisms | Confirmed against ProjectBudget: limits are in the skill text, the agent uses the owner's credentials, administrators can bypass, there is no CODEOWNERS file, and all issue text is read. New ADR-011: human merge in Phase A with a skill that has no merge step; automatic merge only after a separate agent identity, an environment without owner credentials, code-owner review, a CI-computed eligibility check and an input allowlist have been demonstrated. The answer key is kept off agent-accessible machines. | ADR-011; milestones M0 steps 2 and 4–7 | Resolved for Phase A, with the residual risk stated in ADR-011. Phase B preconditions are deferred by design. |
| **F-12** Curriculum is the largest unvalidated scope item | **Resolved differently.** The review recommended deferring all education. The owner keeps a lightweight concept note in V1 and schedules the persistent curriculum as M6. | ADR-005; RFC §6.4, §2.2; milestones M6 | Resolved differently |
| **F-13** Pi assumptions unverified | Checked against the Home System repository: 64-bit Raspberry Pi OS, Docker, systemd, Home Assistant as a container. The Home Assistant OS concern is closed. Storage is documented as microSD boot with an SSD planned; no off-device backup was found. ADR-008 makes on-host verification, reliable storage and a tested off-device restore preconditions for M2. | ADR-008; RFC §9; milestones 0.11–0.13 | Resolved, verification pending: storage, headroom, backup (gates M2) |
| **F-14** Fetcher on the home-automation host; tool calling | No tools and no model-directed fetching. Network policy with post-resolution address checks on every redirect, with acceptance tests. Container has no host networking, no Docker socket and no Home Assistant credentials. Added from the Home System read: briefing content must never enter the email integration's model prompt. | ADR-008; ADR-009 (orchestration); ADR-006 consumer rule 4; RFC §11 | Resolved |

## P2 and P3 findings

| Finding | Resolution |
|---|---|
| F-15 "Reproducible" undefined | Raw responses are stored; briefings are immutable versions rendered from stored content. Replay on full text is limited to 90 days by ADR-010. |
| F-16 Unbounded research loop | Research deferred to M5; escalation is one bounded step. |
| F-17 Provider abstraction level | Task-level interface, one provider, native structured output (ADR-009). |

| F-19 Contract gaps | Status and confidence enumerated, `concept_note` optional, schema and fixtures published, full briefing inline (RFC §8.2, ADR-006). |
| F-20 Corroboration undefined | Source roles and independent source count (ADR-004). |
| F-21 Relevance is audience-relative | One stated reference audience; single default profile (RFC §6.1, §5). |
| F-22 No degraded path | Defined in RFC §7. |
| F-23 Variance unmeasured | First look in M1; formal noise band in M4 (ADR-007 §7). |
| F-24 Thin ADRs | All ADRs now have alternatives, acceptance checks and a specific revisit condition. |
| F-25 ADR-007 and ADR-009 overlap | Evaluation is in ADR-007 only; ADR-009 covers orchestration and observability. |
| F-26 Untestable acceptance wording | Milestone criteria rewritten as observable checks. |
| F-27 Version naming | RFC is v0.3 throughout. |
| F-28 Alembic batch mode | Stated in ADR-002. |
| F-29 Packet zip in the repository root | The v0.2 documents were imported as a baseline commit so the revision shows as a diff. The zip is still untracked and can be deleted or ignored by the owner. |
